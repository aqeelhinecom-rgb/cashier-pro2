# Cashier Pro — تقرير تحسين معالجة الصور والتخزين السحابي (المرحلة 16)

**وثيقة التقرير**: `docs/PHASE16_IMAGE_STORAGE_REPORT.md`  
**تاريخ التنفيذ**: نوفمبر 2026  
**طبيعة المرحلة**: تحسين معالجة وضغط صور المنتجات والمرفقات وتجهيز التخزين السحابي (Image Optimization & Cloud Storage Reliability).  
**حالة قاعدة الإنتاج**: قاعدة **Dexie IndexedDB (`CashierPro_DB`)** محفوظة كمصدر وحيد للحقيقة ولم تُمس، ولم يتم تفعيل Firebase على بيانات المحل الحقيقية، وتم تنفيذ واختبار كافة السيناريوهات في بيئة اختبار ومحاكاة معزولة ومستقلة تماماً.

## 1. تحليل النظام الحالي قبل التعديل (Current System Baseline)

تم فحص ومراجعة آلية حفظ وعرض الصور السابقة:
1. **جدول `product_images` في Dexie**:
   - كان السجل يخزن: `{ id, uuid, productId, base64, blob, mimeType, updatedAt }`.
   - يتم تخزين نسخة Base64 مباشرة على المنتج في حقل `image` لعرضه الفوري في الجداول.
2. **محرك الضغط القديم (`src/utils/image.ts`)**:
   - كان يعتمد على تحويل إجباري لكل الصور إلى صيغة `image/jpeg` بجودة 0.78، مما يؤدي إلى:
     - تدمير خلفيات الشفافية لصور PNG وتحويلها إلى خلفيات سوداء أو بيضاء مشوهة.
     - عدم توليد صور مصغرة (Thumbnails) مستقلة؛ فيتم تحميل الصورة الكاملة داخل خلايا جداول الفواتير ونقاط البيع مما يثقل ذاكرة المتصفح والهواتف.
     - عدم التحقق من البايتات السحرية (Magic Bytes)؛ مما يسمح برفع ملفات غير صورية أو تالفة إذا تم تغيير امتدادها ظاهرياً.
     - عدم وجود بصمة تحقق رقمية SHA-256؛ مما يسبب رفع نفس الصورة مراراً وتكراراً وهدر سعة التخزين والشبكة.

## 2. تصميم التخزين متعدد المستويات الجديد (Multi-Tier Image Architecture)

```
┌────────────────────────────────────────────────────────────────────────────────┐
│                   نموذج التخزين متعدد المستويات (Multi-Tier Storage)            │
├────────────────────────────────────────────────────────────────────────────────┤
│ 1. الصورة الأصلية (Original Image):                                            │
│    • تُحفظ كاملة الدقة والجودة (Full Resolution) كما التقطها المستخدم.         │
│    • تظل متاحة دائماً في الأرشيف والنسخ الاحتياطية للرجوع الجنائي أو الطباعة. │
│                                                                                │
│ 2. الصورة المحسنة (Optimized Image):                                           │
│    • أبعاد مقننة (بحد أقصى 800 بكسل) مع الحفاظ الصارم على نسبة العرض للارتفاع. │
│    • تحويل ذكي لصيغة WebP الحديثة (أو PNG) مع الحفاظ التام على الشفافية (Alpha).│
│    • خفض الحجم بنسبة 70% إلى 90% مع بقاء التفاصيل واضحة لتمييز قطع الغيار.    │
│                                                                                │
│ 3. الصورة المصغرة (Thumbnail):                                                 │
│    • أبعاد متناهية الصغر (150 بكسل كحد أقصى) وحجم خفيف جداً (أقل من 2KB).     │
│    • تُستخدم حصراً في شاشات الكاشير وجداول المبيعات على الهواتف لتسريع التصفح. │
│                                                                                │
│ 4. بصمة المحتوى (SHA-256 Checksum):                                            │
│    • منع تكرار الرفع (Deduplication) لنفس الصورة السحابية عبر العنوان بالمحتوى. │
└────────────────────────────────────────────────────────────────────────────────┘
```

## 3. الملفات المعدلة والمنشأة في المرحلة 16

1. **`src/services/storage/types.ts`**:
   - توسيع واجهة `StorageProductImage` بحقول التخزين متعدد المستويات الاختيارية (`originalImage`, `optimizedImage`, `thumbnail`, `originalWidth`, `optimizedWidth`, `checksum`, `originalSizeBytes`, `optimizedSizeBytes`) مع الحفاظ التام على التوافق الرجعي 100% مع السجلات القديمة.
2. **`src/services/storage/imageOptimizationEngine.ts`**:
   - بناء المحرك المتكامل لفحص البايتات السحرية، والضغط الذكي، والحفاظ على الشفافية، ومحاكاة التخزين السحابي Firebase Storage مع طابور عدم الاتصال (Offline Queue) وإمكانية التراجع (Rollback).
3. **`scripts/run-phase16-image-optimization.ts`**:
   - الجناح الاختباري المنعزل لتنفيذ سيناريوهات الاختبار الـ 14 والتحقق بالأرقام.

## 6. توافق النسخ الاحتياطية وقاعدة البيانات المحلية (Dexie & Backup Integrity)

1. **التوافق الرجعي لسجلات الصور القديمة (Backward Compatibility)**:
   - تم تصميم الحقول الإضافية كحقول اختيارية (Optional Fields).
   - أي سجل صورة قديم يحتوي فقط على `{ id, productId, base64, mimeType }` يظل يعمل في الواجهة دون الحاجة لأي ترحيل قسري أو تدمير للبيانات القديمة.
2. **محرك النسخ الاحتياطي (`dexieBackupEngine.ts`)**:
   - يشمل جدول `product_images` تلقائياً في ملف النسخة الاحتياطية.
   - عند استعادة النسخة الاحتياطية، تُستعاد الصورة الأصلية والنسخة المحسنة والمصغرة مع بصمة SHA-256 الخاصة بها لضمان سلامة النقل.

## 8. المخاطر المتبقية والتوصيات (Residual Risks & Recommendations)

1. **حجم النسخ الاحتياطية المحلية عند تراكم آلاف الصور الأصلية**:
   - تخزين كل من النسخة الأصلية والمحسنة محلياً قد يزيد حجم ملف النسخة الاحتياطية JSON بعد عدة سنوات.
   - **التوصية**: توفير خيار للمستخدم في شاشة النسخ الاحتياطي: *(تصدير النسخة متضمنة الصور الأصلية، أو تصدير النسخ المحسنة الخفيفة فقط)*.
2. **استخدام كاش المتصفح (Browser Cache Headers)**:
   - عند تفعيل التخزين السحابي مستقبلاً، يجب تعيين ترويسة `Cache-Control: public, max-age=31536000, immutable` لملفات الصور التي تعتمد بصمة المحتوى في مسارها لضمان عدم إعادة تحميلها من الإنترنت.
