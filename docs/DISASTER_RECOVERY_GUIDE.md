# Cashier Pro — دليل التعافي من الكوارث واستعادة البيانات (Phase 7B)

## 1. سيناريوهات الكوارث المغطاة
1. **تلف متصفح أو جهاز الكاشير**: تعطل القرص الصلب أو مسح بيانات المتصفح بالكامل.
2. **فقدان قاعدة البيانات بالكامل (Total DB Drop)**: تشغيل النظام على جهاز جديد بذاكرة خالية.
3. **انقطاع الكهرباء أثناء الاستعادة (Power Outage / Crash mid-restore)**: تراجع تلقائي ذري بفضل معاملات IndexedDB.
4. **تلاعب أو تلف ملف النسخة الاحتياطية**: اكتشاف فوري عبر بصمة SHA-256 ورفض الاستعادة قبل أي كتابة.

---

## 2. بروتوكول الاستعادة المعتمد خطوة بخطوة

### الخطوة 1: الفحص الأولي لبصمة الملف (SHA-256 Digest Check)
- يقرأ النظام ملف النسخة الاحتياطية بصيغة JSON UTF-8.
- يقوم بحساب بصمة SHA-256 لكافة الجداول والبيانات.
- يقارن البصمة المحسوبة مع البصمة الموثقة في ترويسة الملف `manifest.checksum`.
- في حال وجود أي تلاعب أو اختلاف ولو بحرف واحد، يرفض النظام الملف فوراً دون لمس قاعدة البيانات الحالية.

### الخطوة 2: فحص التجربة الرملية لجميع الجداول الـ 12 (Sandbox Dry-Run)
- قبل إفراغ قاعدة البيانات النشطة، يتم فتح قاعدة بيانات مؤقتة معزولة (`Cashier_Sandbox_Verify_*`).
- يتم استيراد كافة السجلات والتحقق من تطابق عدد السجلات الفعلي في **جميع الجداول الـ 12** (`products`, `parties`, `invoices`, `invoice_items`, `payments`, `expenses`, `held_invoices`, `categories`, `settings`, `product_images`, `change_journal`, `migration_state`).
- يتم مسح القاعدة الرملية فوراً في كتلة `finally` دون التأثير على ذاكرة الجلسة النشطة.

### الخطوة 3: لقطة الأمان والتنفيذ الذري الكامل (All-or-Nothing Atomic Commit)
- يتم أخذ لقطة أمان تلقائية (`pre_restore_safety`) في `backup_history` قبل المسح.
- تنفذ الاستعادة داخل معاملة ذرية موحدة `db.transaction('rw', allTables, ...)` سواء عبر `restoreDexieBackupSafely` أو عبر `universalRestore` / `DB.restoreDataAsync` (المتوافقة مع ملفات `.db` SQLite والـ JSON).
- يتم تحديث عدادات تسلسل الفواتير (`seq_sale`, `seq_purchase`, `seq_sale_return`, `seq_quote`) آلياً لمنع أي تصادم ترقيم.
- في حال انقطاع التيار الكهربائي أو حدوث أي استثناء، يتولى IndexedDB التراجع التلقائي (Rollback) الكامل، وتظل البيانات السابقة سليمة دون أي تشويه.

### الخطوة 4: التحقق المالي والمخزني ما بعد الاستعادة
عند اكتمال الاستعادة للقاعدة النشطة، يتم تحديث ذاكرة الواجهة فوراً وإظهار ملخص التحقق:
- عدد المنتجات المسترجعة وأرصدة المخزون وصور المنتجات (`product_images`).
- صافي المبيعات، ومجموع الديون، وأرصدة العملاء والموردين بعد خصم المرتجعات واستبعاد عروض الأسعار.
- آخر رقم فاتورة تم الوصول إليه لضمان استمرار التسلسل الآمن.
